Current interface guidance

  • For a military move/attack: “Only Vanguard28 attacks. Other friendly formations do not combine fire.” Use the selected formation's actual name/type/count; retain ordinary command costs and legality checks.
  • When local sensors exist, show “Visible opponent order” using the same current fleet order as the command. Later opponents are conditional: a surviving attacker continues after each exchange; a destroyed attacker stops.
  • In a compact explanation: “Each pair exchanges up to four rounds. A surviving attacker proceeds to the next opponent even if the earlier defender also survived.” Clearing fleets and bombarding a hostile colony remain separate commands.
  • Without sensors, say opposition is unknown. Do not infer hidden fleet numbers, names, types, locations or a safe empty target. Charted hostile sovereignty may still be shown as public context.
  • Under a current orbit list with multiple own formations: “Your formations defend separately in the order shown.” Include civilian classes because they also occupy positions in the existing target order. Hold does not remove a defender from combat.

Approved pure projection

getEngagementPreview(state,fleetId,targetId,factionId='player') returns null for a foreign/civilian/missing fleet, unknown destination, or nonadjacent remote destination. Otherwise it returns systemId, systemName, context, selected formation snapshot, observed, opponents (null if unknown), otherFriendly current formations and hostileColony. Formation snapshots contain only id/name/owner/type/ships/hp/maxHp. No hidden intelligence, live references or historical assertions.

getDefenseOrder(state,systemId,factionId='player') returns own formation snapshots in engine order, including civilians, or an empty list for an unknown system.
