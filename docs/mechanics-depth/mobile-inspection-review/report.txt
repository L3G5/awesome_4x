This is a real default-flow issue. The user is not doing something wrong. Pathfinder f1 is automatically selected before the player chooses any ship. Tapping Velorum's unobscured world label updates the world inspector but retains Pathfinder and interprets the world as its proposed destination. The fleet card expands from 120px to 266px, covering 50.8% of the 523px map. The actual fleet does not move and no orders are spent: full state before/after matches exactly.

Escape clears selection, but touch users have no equivalent visible control. Even then the empty-fleet card occupies 101px. Screens/DOM: 01-fresh-default, 02-world-tap, 03-escape-workaround. These are direct UI interactions with the default campaign, not synthetic fixture states.

Cause: main.js automatically initializes selectedFleetId to the scout; selectSystem retains it; renderFleet treats every different selectedSystemId as a movement/course target. At the existing 660px responsive breakpoint, the map is only 62dvh high while the wrapping fleet/route card remains overlaid on it. Hiding fleet-switch buttons does not remove the auto-selected command context.

Recommended bounded transitions, mobile only:
1. Open/reload/new campaign in world-inspection mode, with no active fleet selection, command card or incidental fleet-dependent inspector previews. Keep one compact Fleet roster button instead of the large empty card. Ordinary world taps inspect.
2. Deliberately selecting an owned fleet through its token, orbit row, roster or N enters fleet-command mode at its location. Make that mode clear: the next world tap chooses its destination. Keep the existing two-step fleet→destination flow.
3. Add a touch-visible Close fleet controls/× action, equivalent to non-modal Escape, returning to inspection. Explicit Inspect/Home/report-world actions also inspect; Back to fleet stays in fleet-command mode. Preserve world-label keyboard focus and modal Escape/focus-trap precedence.
4. Change UI selection/mode only. Closing controls must never Hold a fleet, cancel/replot its saved course, restore movement or spend an order. A remembered fleet ID may remain internally, but an inspecting world must render as having no active fleet. Leave desktop selection/targeting behavior unchanged.

Counterexamples: clearing selection on every map tap would break deliberate fleet→destination commands. Merely hiding the route strip would leave both the selected-ship ambiguity and other fleet controls. Adding a compulsory destination-mode click to every move would impose an unnecessary extra step; explicit fleet selection can arm the existing destination flow.
