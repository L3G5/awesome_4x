Observation and checks

The observer records paid assignment commands immediately, including actual order differences, and brackets every actual fleet-versus-fleet battle. It captures rival-only engagements as well as player-visible battles; that retrospective audit data is never supplied to a policy. Participation means the defender was marked when a real duel began. It excludes attacks by marked fleets, queue entries that never fought, and later flags inferred from final states. First-five event examples are retained per run; counters cover each complete run.

Each measured campaign has a complete uninstrumented validation replay from the same seed. Every complete JSON state matched after all 2,240 rounds and at all 32 campaign finishes. Cycles20/40/60 produced 96 additional exact JSON-reloaded next-round comparisons. All 2,272 initial/post-round measured states and 2,272 raw states validated with finite nonnegative resources and orders. All campaigns finished. The raw replays are validation executions of the same configurations, not another outcome cohort.

Fleet-combat loss counters in the data sum participant losses immediately within actual fleet duels only. They exclude invasions, upkeep and other removals. Different combat order can change later RNG consumption, fleet composition, strategy and exposure; those loss totals are descriptive, not equal-exposure estimates. These fixed seeds and scripted policies are not human win-rate estimates. No further cohort or production source changes were made.

Reproduce

Portable runner requires Node.js and a Git repository containing the two pinned commits, with no installed project dependencies. It extracts the complete source graph to a temporary directory and removes it afterward.

node compare.mjs --repo /path/to/awesome_4x --out results.json
