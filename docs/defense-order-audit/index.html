ASTERION REACH · STAGE 14 DESIGN PROVENANCE

Defender order changes the commitment

This folder separates three kinds of evidence: an actual UI battle, a checkpoint derived by exact replay, and explicitly hypothetical changes to defender ordering. Both experiments use historical pinned engines. They do not test the released Lead defense command or the later zero-fire fractional-hull correction.

1. Actual campaign and verified boundary

In the IRON-COVENANT-10 UI campaign, three Concord frigates and a cruiser occupied Sable before the cycle-41 rival phase. The frigates fought first; the attacking Veyr force died before reaching the cruiser. Two frigates were lost. The campaign subsequently won Domination on cycle 57 without any defensive-order command.

The portable runner reads the original normalized 340-command trace, checks its SHA-256 and all 12 historical engine-source hashes, and replays the first 233 commands. The resulting verified-pre41.json is replay-derived, not an actual download. Its last player-command event is 689. The next recorded endTurn is event 690; the actual cycle-42 export is event 692. There are no intervening game commands. Applying that endTurn to the baseline matches the unchanged actual export in every serialized field, including RNG, rival state and history.

The engine is pinned to 60fd9f8e85edfee92ed40ee29c9b8c314e140da3. Boundary proof, hashes and results record the exact receipt indices. No equality was forced and no unrecorded repair, grant or command was inserted.

2. Hypothetical Sable order-only fork

Starting from that verified pre-41 state, the experiment exchanges only the two own Sable formations' positions in the historical fleet array, then runs the same endTurn. This is not a legal historical UI action and charges no order cost. It isolates the effect of defender sequence; it does not model Stage 14's shared helper, intergovernment ordering or command lifecycle.

3. Fixed synthetic probe: 48 paired cases

The independent review's original four scenarios × twelve seeds are preserved without adding cases. Each pair starts from the same constructed state and RNG and issues one ordinary Veyr attack; only own defender order changes. These are synthetic states, not campaign checkpoints, human success rates or a balance cohort. Their historical engine is separately pinned to d50ed50cb076157ba09fb6e5dd4d0c06652a06ef and bundled locally with verified source hashes.

Reproduce and verify

node docs/defense-order-audit/replay-sable.mjs
node docs/defense-order-audit/compare-synthetic.mjs
node docs/defense-order-audit/verify-artifacts.mjs

Node.js 22 or later is sufficient. The Sable runner deliberately imports the existing sibling historical replay engine; the synthetic runner imports its own separately pinned snapshot. Neither needs network access, a git checkout, the original temporary directories or current game-source imports. Artifact and external-reference hashes cover the copied material. The verifier also resolves every local HTML link.

The actual military run and the hypothetical fork remain separate. A future ordinary-command audit must check the current one-order cost, no-op behavior, per-government ordering, Hold, split/merge, physical departure and save/reload against the final Stage 14 engine. Those are not claimed by these historical design experiments.
